# 烽火剪辑：第一版实施方案

## 目标

Windows 本地工具。用户选择 OBS 原片和 BGM，生成最长 120 秒的击杀混剪；默认目标 90 秒。优先做击杀、音乐和少量特效，暂不做搞笑语音、语音字幕或大型视觉模型。素材不够时输出更短的视频，不循环复制镜头凑时长。

## 当前条件与判断

- 开发机：Intel i5-1235U / Iris Xe，D 盘有充足空间。CPU 编码可验证功能；RTX 5080/NVENC 需在游戏电脑验收。
- 当前没有真实三角洲录像。合成素材能验证检测算法、选片和音视频流程，不能证明国服击杀识别准确。
- FFmpeg 负责解码、裁切、变速、混音、特效和导出；Python 编排；OpenCV 做提示图案匹配；NumPy 分析音乐瞬态与节拍候选。无需训练模型。
- 第一版检测采用可标定的画面提示模板。拿到原片后在出现击倒提示的画面上框选稳定图案，保存为配置；相同分辨率比例与 HUD 布局可复用。不是逐次手动挑高光。UI/HUD、语言、缩放发生变化时需要重新标定。
- 模板检测无法判断“极限操作”或可靠区分所有击倒、补枪、淘汰情形。默认仅称为“候选事件”，以短时多次事件和节奏紧凑程度排序。真实准确率必须单独测量。

## 实施顺序与验收

1. 环境：项目内虚拟环境和便携 FFmpeg/ffprobe，固定 Python 包版本；不更改系统 PATH。下载 FFmpeg 时核对官方提供的 SHA-256，并记录实际版本。
2. 检测与选片：流式扫描 ROI，不将几小时录像展开成图片；合并持续提示、去重、按时间间隔组合片段；输出事件置信度和时间清单。
3. 音乐与渲染：分析用户选定音乐段的瞬态，尝试将关键事件靠近重拍。轻度推近和闪白，保留射击原速；首版不承诺复杂速度曲线或自动识别副歌。CPU 为默认；NVENC 可选，失败会回退并显示提示。
4. 本地界面：选择或填写文件路径、查看视频帧、框选并保存检测图案、调整时长/音乐起点/强度/音量、生成、取消、查看结果与事件。仅监听 127.0.0.1，不上传录像。
5. 自动测试：使用已知事件时间的自制素材，检测精度与去重、剪辑时间预算、音乐偏移、无音轨、无事件、路径空格/中文、任务失败/取消、最终视频解码与时长；检查浏览器界面。
6. 真实素材验收（等待录像）：短样本标定，人工核对误检/漏检，调整扫描频率与阈值；再测试小时级原片、磁盘占用、处理速度和 RTX 5080。未做完前标注为原型。

## 首版边界

- 输入一个完整视频和一个音乐文件，不承诺任意 HDR/10-bit/多屏 HUD 的识别效果。
- 输出 1080p 以内、30 fps、H.264/AAC MP4；不改变原始文件，输出采用独立任务目录。
- 使用 ffprobe 获取音轨；用户可选游戏音轨。混合音轨只能整体调音量，无法可靠分离聊天。
- 音乐时长不足时提示调整，避免无意循环；音乐节拍分析不等于理解歌曲结构。
- 生成过程按阶段显示真实进度，遇到无事件给出说明，不伪造高光。
- 预计项目运行依赖为数百 MB，最终实测。测试录像与任务缓存单列。以后可按需要打包独立应用。

## 风险与决策点

若真实提示变化多、识别不稳定，先比较 OCR 或现成高光工具，避免堆叠无依据的规则。若自动节奏不合口味，先调整几套固定模板。只有短样片达到预期，才扩大模型和特效复杂度。

## 项目布局

`videocut/` 核心模块；`web/` 本地界面；`scripts/` 环境与演示脚本；`tests/` 自动测试；`docs/` 方案和验证记录；`data/` 用户配置；`outputs/` 成片；`work/` 临时文件；`.tools/` 便携工具。所有用户媒体、模型、缓存、依赖及本地配置均被 Git 忽略。
