# 三角洲录制与高光工程

0.4.0 提供“录制 → 整理高光 → 混剪”的完整调用链，已构建含便携录制组件的 Windows 包。已有三角洲短录像在独立窗口播放，经原生捕获、实时 OCR、SQLite 标记和集锦导出的闭环已经验证；真实游戏运行时的性能、声音同步和长局稳定性仍以 [VALIDATION.md](VALIDATION.md) 中的专项记录为准。录像回放与真实游戏验收分开记录。

## 安装与操作

在已完成基础环境安装的 Windows 源码目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\download_capture.py
.\.venv\Scripts\python.exe -m videocut.launcher --open
```

录制组件是固定版本、校验 SHA-256 的便携 OBS/libobs 运行时，附带隔离的 Python。文件放在 `.tools/obs`，不修改系统 PATH、不安装 OBS 服务，不需要用户打开 OBS 窗口。下载需要网络，录制和识别不上传画面。组件未就绪时仍可导入录像剪辑。

当前固定 OBS 32.2.2 的可选在线兼容表更新已通过内部适配停用：在私有临时配置位置建立占位文件，使更新器在创建工作线程前退出，并要求日志确认；收不到确认时捕获进程启动失败。这是针对固定版本的保护，不代表 OBS 默认不联网，也不构成软件所有功能均无需网络的承诺。

1. 在“录制与高光”点击窗口列表旁的“刷新”，明确选择游戏窗口或显示器。选择系统声音或静音、30/60 帧，再开始录制。
2. 自动标记采用固定的三角洲中文默认 HUD 布局。需要至少 720p、16:9 源画面；分辨率、窗口尺寸或 HUD 变化后的识别效果需要重新核对。
3. 录制期间可点击“添加标记”，或在快捷键成功注册后按 `Ctrl+Alt+F8`。手动标记使用当前录制时间轴，不使用页面收到请求的时间。
4. 点击“结束录制”后等待保存与检查完成。录制历史保留原片、事件与选择，刷新页面或重启后可继续整理。
5. 整理页可以预览片段、勾选保留事件、设置统一前后范围、按原片秒数补充标记。新增手动标记自动选中；已经排除的旧标记不会因检测更新而自动复选。
6. “导出原声集锦”导出所有勾选事件。默认从事件首次出现前 5 秒，到该提示结束后 2 秒；重叠范围合并，按原片时间排序。片头与片尾裁到源文件边界。
7. “选择音乐与特效”使用同一工程的标记生成混剪。选择 BGM、目标时长和预设；音乐可不选。混剪默认目标 90 秒、最高 120 秒，会精选片段，原声集锦不受这些上限影响。

特效预设仅有干净剪辑、轻量卡点、击杀冲击，对应现有放大、闪白与效果音的强度 0、0.3、0.7。音乐分析检测能量变化，不理解副歌、乐句或高潮。

## 声音与输出

首版使用当前系统播放设备的输出声音，因此其他应用正在播放的音乐、通话等也可能进入录制。没有麦克风输入开关、按应用音频隔离或自动选择纯游戏音轨。静音录制不连接 WASAPI 声音源，但为兼容封装仍可能带有静音 AAC 轨道。导入模式原有的手选 OBS 多音轨能力继续保留，但不能据此推断内置录制已经分轨。

声音设备不可用或重新连接时，工作台显示提示并继续录制；提示随工程保存，供录后检查可能的静音区间。录制收尾将捕获引擎末尾诊断写入运行日志。设备状态、音轨存在或没有警告都不能代替实际试听及音画同步核对。

图像、系统声音、编码、封装由同一捕获引擎管理。检测只读取带录制时间戳的画面样本；OCR 处理完成的时间不用于标记。后期视频裁切与原声提取消费同一片段时间线。集锦区间向外对齐输出帧，输出偏移按整数帧累计，避免多个片段分别取整引起累计漂移；源文件片尾不足一帧时，仅在最后补齐不足一帧的画面和静音，原片区间仍不越界。

录制源保存在 MKV，界面短片预览与最终导出使用浏览器兼容的 MP4。录制可选 30/60 帧，当前最终剪辑输出仍是 SDR、最高 1080p、30 fps、H.264/AAC。HDR、长时间音画漂移与设备切换都需要独立验证，不能只凭存在音轨即判断声音采集正确。

## 识别与缺口

实时检测位于 `videocut/realtime.py`，预设为 `delta_16_9_v1`。当前提示区域为源画面宽度 35%–66%、高度 59%–78%，采样目标 15 fps；保持区域内源分辨率，不在录制回调中执行全屏 OCR。

捕获、IPC 分发和检测使用有界队列；检测跟不上时报告丢弃或未处理区间，避免无上限积压。轻量亮色/金色门控后才做局部 OCR，并通过跨帧提示变化确定事件。标记包含原始文字、位置、置信依据和状态：

| 状态 | 默认处理 |
| --- | --- |
| `candidate` | 尚未确认，默认不进入选片 |
| `confirmed` | 保留，可人工排除 |
| `needs_review` | 保留并提示待确认 |
| `rejected` | 不进入导出 |

识别器失败时录制仍可继续，用户仍可手动标记。系统记录缺口供录后补查；没有缺口只表示已处理采样，不能证明所有击杀均被发现。固定区域、门控、文字识别以及采样间隔仍会造成漏检。玩家与小兵身份默认不可靠，不将分数当准确率。

“补查整段提示区”对已封存原片使用同一局部识别规则。成功完成后一次事务替换自动事件，保留手动事件；同类型且足够接近的事件一对一对应到旧 UUID。若此前已有人工选择，新发现或身份对应不明确的事件默认不选，并提示重新勾选。部分失败结果不得覆盖完整旧清单。

## 持久数据与接口边界

源码版默认使用项目目录作为数据根；免安装版使用 `%LOCALAPPDATA%/FenghuoClip`。可用既有 `VIDEOCUT_DATA_DIR` 指定独立数据目录。

| 路径 | 内容 |
| --- | --- |
| `data/projects.sqlite` | 录制会话、封存资产、事件、缺口、人工选择与剪辑设置 |
| `data/recording.lock` | 同一数据目录的跨进程录制锁 |
| `recordings/<session_id>/source.mkv` | 原始录制文件 |
| `recordings/<session_id>/previews/` | 按需生成的短片预览，单次最长 45 秒 |
| `recordings/<session_id>/recovered-*.mkv` | 恢复后的独立文件，原始残留不覆盖 |
| `outputs/<job_id>/` | 最终视频、事件清单、选片与设置清单 |

SQLite 使用 WAL、同步事务和写锁保护修订检查。事件时间持久化为整数微秒，事件 ID 在提示尾部延长或证据变化时保持稳定。已经明确清空的选择不会被后续自动事件重新填满；新增手动事件体现用户主动选择，自动选中一次。

完整事件快照由服务端 `ProjectStore.build_generation_spec()` 建立，得到普通设置和冻结的 `RecordingSource`。后者包含会话、原始资产版本、编辑版本、事件 JSON、选中 ID 以及前后范围。`pipeline.generate(..., recording_source=...)` 直接使用这些事件，不重新扫描，也不使用客户端提供的事件数组。导出开始后再修改工程，不改变正在渲染的快照。

文件正在录制时没有“最终签名”。停止捕获、完成封装并验证媒体后，`finalize_asset()` 保存路径、大小、修改时间组成的签名与媒体信息。导出前后都检查签名；原片变化时拒绝把旧事件应用到新文件。该签名用于检测意外替换，不是完整媒体内容的密码学认证。

基础集锦与混剪都从原始录像取片。基础集锦的导出文件只供播放或保存，不成为下一次混剪的输入，因此不额外叠加一次视频有损编码。输出清单保留工程版本、原片片段范围与成片偏移。

## 停止、退出与恢复

录制主要状态是 `starting → recording → stopping → finalizing → ready`。普通渲染取消走原有任务 `Context`，捕获进程由独立管理器发送停止请求、等待排空和封装确认，不能用普通导出取消来强杀录制。清理结束前继续视为忙，不允许新录制覆盖旧进程或锁对象。

正常停止会排空尾部采样并等待协议读取、日志和回调分发线程退出，确认回调排空后才视为正常收尾。捕获与检测回调绑定创建时的会话；旧会话迟到的标记、缺口或状态消息不能写入下一段录制。检测收尾失败时保留已封存录像，并提示录后补查。

启动时管理器先尝试取得录制锁，取得后才将遗留活跃会话标为 `interrupted`。另一个服务正在持锁录制时，只打开页面不会把它标为中断。失败或中断文件不会自动删除；“恢复中断录像”尝试重新封装到新文件，再检查并建立新的封存资产版本。

MKV 和独立恢复路径减少异常损失，但不能保证断电时最后一段画面或声音一定完整。正常使用应先结束录制，等“已保存”后再退出。源码已加入低磁盘空间时停止录制的保护，不能代替提前预留录制空间。

没有自动删除录制、预览或导出缓存。备份前退出应用，一起保存 `recordings` 与 `data/projects.sqlite`；SQLite 正在运行时单独复制主数据库可能漏掉 WAL 中未归并的最新事务。

## 验收边界

测试分为存储与状态机模拟、真实 FFmpeg 文件导出、真实录像实时回放、原生窗口/系统声音录制、真实三角洲边玩边录及小时级测试。前一层通过不意味着后一层通过。

本轮最终完整测试为 234 项 Python、41 项前端通过。真实录像窗口闭环中，40 秒既有三角洲样本通过独立 1920×1080 窗口播放，用 WGC/QSV 30 fps 录得 45.311 秒源片；675 份采样全部接收与处理，得到两条确认标记、零检测缺口，保存到 SQLite 后生成 15.2 秒集锦并完成全片解码。报告为 `work/capture-real-replay/run-1791450826518513500/report.json`。首轮回放窗口底部存在 38 像素白边，中央提示区域与时间映射检查未受影响；修正窗口几何后单独检查确认白边消失，没有重跑完整闭环。这次关闭了系统声音，不用于评价游戏音效保留、系统声音采集或音画同步；也没有运行游戏进程，因此不提供游戏帧率影响指标。

最新 WGC/QSV/WASAPI 短录制回归为 2.333 秒、70 帧、30 份提示区域采样，确认正常停止、回调排空以及固定版本兼容表更新停用，录制与分析均无丢帧。证据为 `work/capture-offline-stop-final.json` 及同名日志、MKV；这一短窗口测试不代替长局、声音设备切换或同步测试。

当前首版没有暂停、自动随游戏启动、常驻回放缓存、自动删除原片、麦克风分轨、多游戏配置或完整人工剪辑时间线。固定提示布局外的游戏模式、语言、HUD 和超宽屏需要单独适配。发布包是否包含录制运行时、干净 Windows 是否能启动和目标 GPU 是否能稳定编码，以实际构建与目标机器测试为准。
