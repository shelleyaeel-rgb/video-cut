# 烽火剪辑

个人使用的本地游戏混剪原型：选 OBS 录像、选 BGM，扫描提示图案，自动挑片段、按音乐瞬态调整节奏，加轻度放大／闪白／效果音，导出 MP4。

**当前没有经过真实三角洲录像校准。** 内置合成演示用于测试流程，不等于已经具备准确的游戏高光识别能力。实施方案见 [docs/PLAN.md](docs/PLAN.md)，实测记录见 [docs/VALIDATION.md](docs/VALIDATION.md)。

## 在这台电脑上启动

双击项目根目录的 `start.cmd`，浏览器会打开本机工作台。保持启动窗口运行；关闭工具时可在窗口按 Ctrl+C。

或运行：

```powershell
.\.venv\Scripts\python.exe -m videocut.launcher --open
```

默认地址 `http://127.0.0.1:8765`。端口被占用时可指定 `--port 8766`。只监听本机地址，媒体不会上传，运行时无需网络。

## 先体验演示

1. 点击“没有素材？体验合成演示”。首次会生成一段包含四个已知事件的测试视频与自制节拍音乐。
2. 等待文件路径和“合成演示专用”配置填好。
3. 点击“生成混剪”。演示目标约 16 秒，便于快速验证；真实使用可设置 60–120 秒。
4. 完成后直接预览，或打开输出文件夹。每次生成都有独立目录，不覆盖原片。

## 有真实录像后的操作

1. 选择本机 OBS 视频和音乐。可使用选择按钮，也可从文件属性复制完整路径。
2. 首次使用，在“首次标定提示图案”输入一个出现击倒提示的原片时间（秒）。读取画面，框选稳定图标或固定文字，避免玩家名、变化数字、场景背景。也可以展开“用数字设置框选范围”，用百分比输入位置与尺寸。
3. 保存配置。这是一次性的识别标定，不需要每次筛选高光。更换 HUD、宽高比或提示样式时重新标定。
4. 设置目标时长、音乐起点、特效强度和音量。“声音与高级设置”里可保留录像人声、手选 OBS 独立游戏音轨，或使用 AI 减弱混合音轨中的人声；BGM 可单独选择 AI 提取伴奏。默认两者都保留。AI 可能影响游戏音效，详见 [docs/AUDIO.md](docs/AUDIO.md)。
5. 点击生成，首次查看镜头来源、核对误检／漏检。默认检测阈值 0.82，越低越容易误检。

仅以稳定提示出现为依据。不会自动断言“一打三”“灭队”或理解精彩程度。同一提示长时间不消失会合并为一个事件；若连续击倒只改变提示数字，需要在真实素材阶段增加识别方法。

## 在另一台 Windows 电脑上安装

准备 **Python 3.12 x64** 和网络，复制源码（无需复制 `.venv`、`work`、`outputs`），然后：

```powershell
# 若使用本机已安装的 Python，请显式传入路径。
.\scripts\setup.ps1 -Python 'C:\完整路径\python.exe'
```

在当前 Codex 环境中，脚本也能定位已提供的 Python。安装会创建项目内 `.venv` 和 `.tools`，不更改系统 PATH。NumPy/OpenCV 版本固定；下载按 PyPI 的 SHA-256 校验。FFmpeg 从 Gyan 官方构建站下载，校验发布者提供的 SHA-256，实际下载信息在 `.tools/ffmpeg-download.json`。若 PyPI 文件下载慢，可加 `-PackageMirror 'https://mirrors.aliyun.com/pypi'`，仍使用 PyPI 官方哈希核验；本次 OpenCV 安装使用了这个镜像。

此处虚拟环境依赖安装时的 Python，不可直接当作独立安装包搬走。若以后要做单文件 EXE，需要额外打包与干净机器验证。CPU 模式默认可用；NVIDIA 模式需要合适驱动和硬件，失败会提示并回退 CPU。

需要 AI 人声处理时，额外运行 `.\.venv\Scripts\python.exe scripts\setup_audio.py` 下载约 64 MiB 的模型。本次电脑已完成安装；AI 音频使用 CPU，NVIDIA 选项只用于视频编码。

## 文件和空间

- `outputs/<任务ID>/montage.mp4`：成片。
- `outputs/<任务ID>/events.json`：候选事件时间、置信度。
- `outputs/<任务ID>/manifest.json`：选片时间线、参数、提示与实测用时。
- `data/profiles/`：用户标定的检测模板。
- `work/jobs/`：候选片段和效果音缓存；只存选中的片段，不保存全片逐帧图片。
- `work/demo/`：合成演示素材。
- `work/audio-cache/`：成功的人声分离结果，可跨任务复用；不自动清理。
- `work/logs/`：当前启动、运行、任务、FFmpeg 和页面日志。
- `work/errors/`：旧版留下的错误日志，保留但不再写入。
- `work/downloads/`：下载缓存，可在确认安装成功且无需离线安装后自行清理。

任务缓存便于排查，当前不会自动删除。原片始终只读。上述媒体、缓存、依赖和本地配置已加入 `.gitignore`，上传源码前仍应检查提交内容。

## 出错时查看日志

点击页面顶部的 **“打开日志文件夹”**，或直接进入项目下的 `work\logs`。也可以点击 **“下载日志”** 保存 ZIP，包含当前日志和轮转备份，不含录像。受限环境无法打开资源管理器时，页面会显示可手动复制的完整路径。页面报错会显示错误编号；已启动的剪辑任务另有任务编号。把编号、发生时间和当时的操作一起提供，就能定位对应记录。启动失败时也可直接打开这个目录，无需网页正常运行。

| 文件 | 记录内容 | 单文件大小 / 备份数 |
| --- | --- | --- |
| `startup.log` | 启动环境、依赖和工具版本、端口占用、依赖缺失、启动异常堆栈 | 2 MiB / 2 |
| `runtime.log` | 无效路径、参数校验、标定和接口异常，带请求编号 | 5 MiB / 3 |
| `tasks.log` | 任务开始、进度、素材参数、候选与镜头数量、完成、取消、失败堆栈及耗时 | 5 MiB / 3 |
| `ffmpeg.log` | FFmpeg/ffprobe 命令参数、逐行诊断输出、退出码、超时、取消及耗时 | 10 MiB / 4 |
| `frontend.log` | 页面捕获的运行错误、未处理异常和 Promise 拒绝，带页面错误编号 | 2 MiB / 2 |
| `bootstrap.log` | 用 `start.cmd` 启动时 Python 缺失或无法启动的简短记录 | 约 64 KiB / 1 |

文件按需创建，以 UTF-8 JSON Lines 保存（每行一条记录）。超过大小后自动轮转为 `.log.1`、`.log.2` 等，最旧备份自动淘汰；总占用约 **102 MiB**，不含历史 `work/errors` 和媒体缓存。FFmpeg 在轮转保留期内保存全部 stderr 诊断文本；页面只显示末尾摘要，不记录视频帧或音频二进制内容。硬件编码回退 CPU 时保留原始失败原因。

日志包含本地素材路径、参数和系统版本，保存在本机，不自动上传；会话令牌及常见凭据字段会脱敏。可以用记事本打开日志并搜索编号。

服务断连时，当前页面最多暂存最近 20 条错误；连接恢复后自动补交。服务重启后如提示会话失效，刷新同一个标签页即可补交。关闭标签页会丢失尚未补交的记录；如果浏览器禁止暂存，页面会提示刷新也会丢失记录。脚本尚未加载、浏览器崩溃、断电或进程被强制结束时，无法保证有最后一条错误记录。日志无法写入时，页面会提示检查空间和权限。

`python -m videocut.server` 旧启动方式仍可用，也会经过同一个启动日志入口。

## 测试

```powershell

# 包含真正解码、识别、渲染、混音和全片解码校验

# 同时验证已安装的 AI 人声模型
```

## 第一版限制

- 支持单视频、单 BGM；输出 SDR、最高 1080p、30 fps、H.264/AAC。HDR 素材明确拒绝，不做未经验证的色彩转换。
- 使用单一稳定提示模板；小图标、动态背景、不同提示布局会影响识别。未加入 OCR、语音识别或视觉大模型。
- 音乐分析检测能量突变点，靠近切点时尝试对齐；不保证理解强拍、乐句、高潮或自动选副歌。
- 特效为固定模板；没有字幕、复杂转场、抠像或人工编辑时间线。
- 人声分离使用现成音乐模型，属于试验功能；不能保证干净去除玩家、队友语音或完整保留枪声，真实游戏处理效果仍需试听。
- 没有高光时会失败提示；高光少时输出短片。音乐剩余时长不足时缩短上限，不自动循环歌曲。
- 办公电脑验证 CPU 路径，游戏电脑的 RTX 5080、小时级吞吐、真实素材准确率待实测。
- 服务重启后任务面板不恢复历史，但已完成的视频和清单保留在 `outputs`。
