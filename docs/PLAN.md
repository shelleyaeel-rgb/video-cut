# 烽火剪辑：设计与实施记录

## 2026-10-08 录制工程链路

当前源码新增录制、整理高光、混剪三步。工程设计与具体操作见 [RECORDING.md](RECORDING.md)，验证证据见 [VALIDATION.md](VALIDATION.md)。后文保留 0.3.0 导入扫描链路的实现记录，避免把原有发布包与新增录制能力混为同一验收范围。

录制由独立 libobs 进程负责图像、系统声音、编码与封装，Python 管理器通过 IPC 获取带原始时间戳的提示区域样本。实时检测在另一独立进程中进行，使用有限队列、轻量门控和局部 OCR；录制不等待 OCR。队列积压、检测故障和未完成区间显式留下缺口，录后允许补查。

`project_store.py` 使用 SQLite 事务保存会话、封存资产、稳定 UUID 标记、微秒时间戳、缺口与编辑版本。活跃文件不计算最终签名；停止收尾并检查媒体后才封存，导出前后核对该签名。启动时只有取得跨进程录制锁的管理器才能将遗留活跃会话标记为中断，单纯打开第二个页面不会中止现有录制。

原声集锦和混剪共用原片与事件工程，但使用不同选片方式。`plan_collection` 保留所有勾选事件，按原片顺序合并重叠范围，不受混剪时长预算或 10 秒镜头上限限制。混剪复用 `plan_clips` 的精选与音乐节奏规划。`RecordingSource` 固定服务端工程版本和事件快照，浏览器只能提交工程 ID、选择和设置；不能用请求里的原始事件冒充可信检测结果。两种导出均读取原始资产，避免集锦再次有损编码。

停止录制与普通导出取消隔离：捕获进程不加入 `media.Context` 的可强杀进程集合，需经停止、排空、封装、检查后才能显示“已保存”。录制清理结束前不接受新录制。异常文件保留，恢复另写新文件，不能把可恢复容器当作不会丢失末尾的保证。

实施验收顺序为：录制与声音完整性 → 时间轴与持久标记 → 实时检测资源隔离 → 基础集锦 → 音乐混剪 → 原生游戏长录制与打包验证。单元测试、真实文件回放、原生窗口录制和真实游戏边玩边录分别记证据，不能互相代替。

## 0.3.0 导入扫描链路

## 目标与界面

Windows 本地工具：选择三角洲录像，自动寻找击倒／击败提示，预览候选事件，再生成最长 120 秒的混剪，默认目标 90 秒。音乐可选，素材不足时输出较短视频，不复制镜头凑时长。

首页只展示素材、扫描预览与生成三个步骤。声音、编码、旧模板和阈值收进高级面板；日志、更新与合成演示收进“工具与应用信息”。默认自动模式不要求用户框选或标定，手动单模板和多模板配置仍可使用。

## 自动识别

`videocut/autodetect.py` 使用本地 RapidOCR 现成中文文字检测／识别 ONNX 模型，并非经过三角洲样本训练的专用检测模型。

1. 在全画面自动发现文字候选，按候选位置放大局部文字识别，不依赖用户指定 ROI。
2. 结合“击倒／击败／击中头部击败”等短提示文字及邻近白色或金色图标确认候选，保留原始文字、位置和分数作为复核依据；过滤“击败若干名敌人”等任务句式。
3. 根据连续帧跟踪提示，同一持续提示去重；内容或类型更新时尝试识别新事件。低质量文字和动画仍可能导致误检、漏检或事件拆分不准。
4. 玩家与小兵默认标为待确认；不把识别置信度当作击杀准确率，不自动断言灭队或目标身份。击倒到补杀的可靠目标关联仍待实现。

扫描采用流式解码，不将完整录像展开成逐帧图片。缺少依赖或模型时显示具体原因，扫描时不联网下载资源。旧模板检测继续提供背景蒙版、独立阈值和人工配置的玩家／小兵辅助标记。

## 预览、排除与复用

- 默认扫描整段，也可指定起点和 5–60 秒片段；均支持取消、查看原片帧和勾选排除。
- 完整扫描清单保存在当前服务会话，绑定视频文件信息、配置及签名；生成时验证后复用，局部结果不会替代全片扫描。
- 整段复核以 `event_id` 精确排除；局部复核的时间段至多匹配一个候选，歧义时报错。录像或配置变化会使旧记录失效，要求重新扫描。
- 输出区分全部候选、过滤事件、实际入选事件及最终镜头数量。排除事件不会触发剪辑，但可能出现在其他镜头的前后范围内。

## 选片与导出

默认前置 5 秒、后置 2 秒；单次提示持续时间最多增加 3 秒尾部。相邻事件合并为交战镜头，单镜头不超过 10 秒，长交战按事件边界拆分。按事件密度和识别依据排序，在目标时长内选片，不把所有候选数等同于最终镜头数。

FFmpeg 负责解码、裁切、特效、混音与导出，NumPy 分析音乐瞬态。轻度放大、闪白与效果音可调；原声／BGM 分别控制，AI 人声处理为试验功能。输出 SDR、最高 1080p、30 fps、H.264/AAC MP4；CPU 默认，NVENC 失败时记录原因并回退。

## 依赖与验证

0.3.0 免安装包包含 Python、FFmpeg、RapidOCR 中文模型及人声模型，素材仅在本机处理。运行依赖固定在 `requirements.txt`：ONNX Runtime 使用 1.20.1，本机 1.22.1 曾有 DLL 加载失败；OpenCV 统一使用 `opencv-python`，避免与 headless 发行包争用同一模块。

验证分三层：自动测试检查提示筛选、去重、排除协议、选片边界及 HTTP；合成视频检查解码、渲染、音频和导出；真实三角洲短样本人工核对误检／漏检。已经取得真实录像，实际测试范围和结果统一记录在 [VALIDATION.md](VALIDATION.md)。短样本不证明跨场景准确率或小时级吞吐，RTX 5080 仍需在目标电脑验收。

## 后续决策

继续补充明暗背景、连续击倒、补杀、相似 HUD、队友播报及无提示样本，分别统计漏检、误检和重复计数。先依据实片修正提示识别与时间跟踪；若仍不稳定，再评估标注数据和专用检测模型，避免把增加规则等同于效果提升。

项目布局保持不变：`videocut/` 核心、`web/` 界面、`scripts/` 环境与打包、`tests/` 测试、`docs/` 文档；用户媒体、模板、模型、缓存、依赖与成片不提交源码仓库。
